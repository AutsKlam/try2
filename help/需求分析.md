# 需求分析：版本备份

## 目标

用最少指令把工作备份到远程，并留下**修改时间 + 简要说明**。不追求完整 git 工作流。

## 对人暴露的能力（仅三条）

1. **git更新**：无条件备份（自动暂存、对齐远程、写备注、提交、推送）。
2. **历史版本**：看已备份列表。
3. **版本撤回**：用新提交恢复到某备份（安全，不强推）。

对应脚本：`help/scripts/git-update.sh`、`history.sh`、`revert.sh`。Agent 只调脚本，不逐步拼 git。

## 设计取舍

| 要 | 不要 |
|----|------|
| 一条指令做完备份 | 让用户先对齐、再暂存、再提交、再推送 |
| 自动记时间与摘要 | 一堆「看 diff / 看状态」日常命令 |
| 分叉时自动 rebase | 动不动停下问「对齐远程」 |
| 冲突才停下 | force push、改写历史 |

## 非目标

- 不替代分支策略、PR 评审、复杂合并。
- 不上传 `.cursor/`（Skill 留本机）。
