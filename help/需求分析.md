# 需求分析：用 Agent 管本仓库

## 目标

在同一个 Agent 对话里管理 git：少打长句、能看清各版本改了什么、能给每个版本留下可读备注。本地 `help/` 给人用；`.cursor/skills/git-repo-ops/` 给 Agent 用。两边共用同一套指令名。

## 三个能力

### 1. 快速输入指令

- 痛点：每次都要重新组织「帮我看 diff / 提交 / 对齐远程」。
- 做法：`指令卡.md` 提供固定短句；Agent 按技能里的别名表执行，不要求用户记得 git 子命令。
- 约束：提交、push、破坏性操作仍须用户明确说出对应指令（或等价原话），Agent 不主动做。
- 例外短句：`git更新` 本身就等于授权「提交当前改动 + 记录时间与简要修改 + push」。不含 force push。与远程分叉时必须先对齐，不能当更新成功。
- `git更新` 默认不把 `.cursor/` 加入版本库（Skill 留在本机）。要共享 skill 须单独说明。

### 2. 查看各版本改动

- 范围：工作区 vs HEAD、暂存区、任意两次提交、本地 `main` vs `origin/main`、指定文件的历史。
- 输出：先结论（ahead/behind、冲突风险），再文件列表，再按需贴关键 diff；默认中文、短段落。
- 不把完整 `git log` dump 当答案。

### 3. 更新各版本备注

- 备注写在 `help/版本备注.md`，按提交哈希索引，不 amend、不 rewrite。
- 新提交之后：用 git 信息补「摘要 / 涉及文件」，「备注」栏留给人或后续指令。
- 用户说「给某某版本加备注」时只改备注文件，除非同时要求提交该文件。
- `git更新` 把摘要写成修改内容的一两句话，并记录本地日期时间；用户加了 `备注：` 则写入备注栏，否则备注与摘要相同。

### 4. 历史版本与撤回

- `历史版本`：只读列出近期提交（哈希、时间、说明、备注），供复制。
- `版本撤回 <哈希>`：用新提交把跟踪文件恢复到该版并 push；保留 `help/版本备注.md` 不整文件回滚；不做 `reset --hard` / force push。

## 角色分工

| 谁 | 做什么 |
|----|--------|
| 人 | 从指令卡复制发送；决定是否提交/推送；写主观备注 |
| Agent | 查 git、解释差异、更新备注文件、仅在被点名时 commit/push |
| 技能 | 把短指令映射到固定步骤，防止漏看远程分叉或漏写备注 |

## 非目标

- 不替代 GitHub 网页上的全部操作。
- 不自动 force push、不改 git config、不跳过 hook。
- 帮助夹不是代码文档；业务说明仍写在仓库其它文件。
